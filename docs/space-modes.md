# 空间模式：共用推演核，分叉空间后端

给后续实现横版（侧视平台动作）用的工作说明。拍板见 [ADR 0043](adr/0043-shared-kernel-split-space.md)。术语以 [CONTEXT.md](../CONTEXT.md) 为准。

**现状：** V1 只实现俯视平面（`TopDown`）。横版未编码。未抽空间接口前，不要在宿主里用向下 `MoveDirection` 冒充重力，也不要另开一套伤害/Buff 核。

---

## 结论（先读这四条）

1. **框架共用，空间分叉。** 确定性 Tick、命令/事件、属性、伤害管道、Buff、技能时间轴、资源、RNG、配置校验继续长在本仓同一套核里。
2. **不要重写战斗框架。** 两套核会在暴击、快照、死亡清理上漂移；真正贵的正确性已经在现有核里。
3. **不要把两种移动揉进当前 `BattleInstance`。** 俯视是缩短/取消位移、不滑墙；横版要重力、接地、站在 AABB 顶边。用模式开关散落在技能/击退/Brain 里会拆掉 V1 契约。
4. **一张图一种模式。** 创建 `BattleInstance` 时选定 `TopDown` 或 `SideView`，同场不混用。

横版第一目标是空洞骑士 / Dead Cells 一类实时技能动作，不是格斗帧对战。格斗（帧表、取消、判定跟动画帧绑定）仍不进本核。

---

## 什么共用、什么分叉

| 共用（现有核，继续长） | 按空间后端分叉 |
|---|---|
| 逻辑帧 30Hz、Fix64、战斗整数、分层 RNG | Y 的语义：平面轴 vs 高度 |
| Command / Event / Query、Tick 阶段、实例隔离 | 占用形状：圆 vs 胶囊或站立 AABB |
| Attribute、Modifier、伤害管道、护盾 | 碰撞：缩短位移 vs 接地 / 贴顶 / 可选贴墙 |
| Buff、控制、资源、CD、死亡与复活 | 移动：全向 MoveSpeed vs 水平走 + 重力 + 跳 |
| 技能时间轴与效果列表（伤/治/盾/Buff/弹/区域） | Facing：全圆 1024 档 vs 逻辑上左右（仍可用档位存 ±X） |
| 配置校验、JSON 加载 | 击退：平面缩短 vs 水平冲量 + 垂直冲量 + 落地 |
| | Brain：平面 ChaseAttack vs 会走台、跳沟 |
| | 地形：纯阻挡盒 vs 可站立顶边、以后再谈单向台 |

技能效果应描述「对过滤后的目标造成伤害 / 施加击退」，不要假设 `FixVector2.Y` 的含义。选敌几何（圆/扇/环）可以两边都用；横版以后可以加轴对齐攻击盒，不必第一天替换全部圆。

## 空间服务该挡掉什么

从 `BattleInstance` 抽出一组**只负责空间**的能力，战斗阶段只调用它，不直接解释地形。第一版接口不必一次完美，但调用点应集中。俯视现状对应的职责：

- 本帧常规位移（`MoveDirection` / `MoveTo`）与技能位移（冲锋、击退、拉人、投掷）
- 位置是否合法（边界、地形、敌对占用）
- 弹体沿线段扫掠命中（已有 `SweptGeometry`）
- 朝向如何从瞄准向量得出
- Carry 结束时的合法落点

横版后端在同一组职责上换成另一套实现。**抽接口时俯视行为必须零变化**：现有 `tests/` 全绿才算抽取完成。

当前耦合点（抽取时优先切断，勿在这些文件里加 `if (SideView)`）：

- `BattleInstance.Movement.cs` — `FindMovementFraction`、`IsPositionValid`
- `BattleInstance.Skills.cs` — Dash / Knockback / Pull
- `BattleInstance.Carry.cs` — 跟随与落点
- `BattleInstance.Projectiles.cs` — 地形与角色扫掠
- `Brains/` — 走位与射程
- `Math/Facing.cs` — 全圆档；横版可读 X 符号，不要另造一套角度系统除非拍板改 CONTEXT

## 横版后端最低范围（编码时再开 ADR 钉细节）

未单独立 ADR 前，按下面做，避免做成格斗核或完整物理引擎：

- X 水平，Y 向上为高度；地图边界仍是矩形。
- 每逻辑帧施加重力与最大下落速度（定点，配置进 Map 或 Battle Config）。
- 接地：圆或盒与地形 AABB **顶边**接触且速度向下或为零，则视为落地，可走、可跳。
- `MoveDirection` 的 Y 分量在横版忽略或拒绝（只认水平）；跳跃是独立命令或技能效果，不是「向上移动」。
- 击退拆水平和垂直；浮空中不按俯视「缩短到墙前停下」冒充落地。
- Root 停水平移动，是否停下落另开 ADR；在拍板前不要用 Root 卡住坠落。
- 第一版不做：斜坡、移动平台刚体、弹性碰撞、可变 dt、单向台、二段跳细节表、土狼时间——需要时各开 ADR。

明确拒绝的捷径：

- 宿主每帧塞一个向下的移动命令当重力（定身会停掉下落，MoveSpeed 会同时管走和掉）。
- 把俯视 `(x, y)` 在表现层画成侧视却仍让 AI 朝「屏幕上下」走，并称之为横版。
- 为横版复制伤害管道、Buff、技能时间轴到另一个仓库。

## 建议实现顺序

1. **抽空间接口，只接上现有俯视实现。** 无行为变化，全量测试绿。
2. **配置增加 `spatialMode`（名可再定），默认 `TopDown`。** 缺省行为与今天完全一致。
3. **实现 `SideViewSpace`：** 重力、接地、水平移动、跳；地形顶边可站。单测用窄平台与墙，锁落地与「不会穿顶」。
4. **击退 / Dash / Carry 落点走空间后端**，不要在技能文件里写第二套位移。
5. **Brain：** 横版先 Idle + 水平 Chase；会跳沟的 Brain 后做。
6. **Facing：** 横版施法仍更新朝向，但移动只消费左右；全圆档可保留以免改事件协议。

同场混用两种空间模式不做。需要「侧视演出的俯视砍杀」时，用 `TopDown` + 宿主表现，不要开 `SideView`。
